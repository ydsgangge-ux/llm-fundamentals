PART 2 · 钻进向量空间

参数不是玄学，是几何

前面每个模块内部处理的都是向量——一串几百到上万维的数字。这里抓住三件真实发生的事：意义是位置、注意力是方向对齐、每一层是微调，不是重写。

③ 残差流：处理不是"改写"，是"层层加注"

跟踪"它"这个token的向量，走过 Transformer 每一层发生了什么
Layer 0刚查表得到的"它"，还不知道指代什么
Layer 1加入"服务员/端来"的语法结构线索
Layer 2方向开始向"名词性代词"靠拢
Layer 3 ★和"咖啡"向量强烈对齐——指代消解完成
Layer 4继续融合"很烫"带来的谓语信息
Layer N向量已"知道"自己=滚烫的咖啡，可参与预测

这就是残差连接在真实发生的事：每一层不会把向量推倒重写，只是在原向量上加一个小更新量（Δ）。轨迹是连续漂移，不是随机跳变——早期层学到的信息始终留在向量里，深层只是不断叠加新理解。这也是为什么几十上百层的网络能稳定训练。

PART 3 · 钻进矩阵空间

矩阵，才是大模型真正的"工作台"

前面用2D散点理解了"意义是位置"，但模型内部真正在算的不是散点图——是矩阵乘法。这一部分把每一步数据处理还原成矩阵网格：你能看到文本怎么变成矩阵、注意力分数怎么算出来、多头怎么切分、MLP怎么升维降维。每个数字都是真算的。

① 分词矩阵化：文本怎么变成数字矩阵

BPE 合并过程 → Token ID → One-hot → Embedding 查表
Step 1: Token IDs → One-hot 编码（每个ID变成词表维度的一行，只有对应位置是1）
↓
Step 2: One-hot × Embedding 矩阵 = 查表得到每个 token 的语义向量
BPE真实分词器不是按字切，而是用 BPE（Byte-Pair Encoding） 算法：从单个字符开始，反复合并训练语料里出现频率最高的相邻字符对，直到词表填满。这样常见词会成为一个整体 token，罕见词被拆成子词——这就是为什么"_university"可能是一个 token，但"_supercalifragilistic"会被拆成好几块。

② QKV 投影：一次矩阵乘法的真相

输入矩阵 X × 权重矩阵 Wq/Wk/Wv = Q/K/V 矩阵 · 点"逐步演示"看矩阵相乘过程
点"逐步演示"看 X × W = Q 的矩阵相乘过程。每个 Q 矩阵的元素，都是 X 的一行和 W 的一列做点积算出来的。真实模型里 Wq/Wk/Wv 是三个不同的权重矩阵，训练过程中各自学会了不同的"投影方向"——Q 学会"我在找什么"，K 学会"我能提供什么"，V 学会"如果被选中，该贡献什么"。

④ 多头分块：一个向量怎么被切成多个头

d=6 维向量 → 切成 3 个头 × 2 维 · 每个头独立算自己的注意力
分头真实模型不会只算一次 Attention。以 d=4096、32 头为例：4096 维向量被均分成 32 段，每段 128 维，每段独立做一次完整的 softmax(QKᵀ/√d)·V。32 个头的输出最后 拼接（concat） 回 4096 维，再乘一个 Wₒ 投影矩阵压缩回原维度。不同头能关注不同维度的关系——语法、指代、情感、因果，各管一摊。

⑤ MLP 矩阵流：升维 → 激活 → 降维

d → 4d → d · 这是模型"记忆知识"的主要容量所在
MLP 是两步矩阵乘法夹一个激活函数：FFN(x) = (SwiGLU(x·W₁) ) · W₂。第一步 W₁ 把向量从 d 维升到 4d 维（比如 4096→16384），在更高维的空间里做非线性激活，第二步 W₂ 再降回 d 维。升维的意义是：高维空间里更容易把不同的概念"分开放"，再通过激活函数筛选出有用的组合。大模型大部分参数都堆在这两个矩阵里。

⑥ RoPE 旋转编码：位置信息怎么"转"进向量

拖动滑块看不同位置的 Q/K 向量被旋转了多少角度
位置 pos: 3
维度对 dim: 0
RoPERoPE 不是把位置信息"加"到向量上，而是按 token 位置把 Q、K 向量旋转一个角度。位置越远，旋转角度越大。两个 token 相距越远，旋转角度差越大，点积自然衰减——相对位置信息从旋转角度差里自动算出来。拖动滑块：左边的向量是原始 Q，右边是旋转后的 Q，角度 = pos × θ，其中 θ = 10000^(-2i/d)。低维对旋转快（位置区分精细），高维对旋转慢（能区分很远的位置）。

② KV Cache：为什么逐词生成不会越来越慢

每生成一个新词，之前的 K/V 不需要重新算——缓存下来直接复用
没有KV Cache时，生成第 N 个词需要重新计算前面所有词的 K 和 V，复杂度是 O(N²)。有了Cache：之前算过的 K/V 直接从缓存读取，每一步只需算新词一个的 Q/K/V。这就是为什么你看到 ChatGPT 前几个词出来得慢、后面越来越快——前面在填充 Cache，后面只增量计算。但代价是：长对话的 Cache 会吃掉大量显存，这也是长上下文模型最难优化的工程问题之一。

③ 学习率调度：训练过程的"油门曲线"

Warmup → Cosine Decay · 学习率不是恒定的，而是先升后降
■ Warmup 阶段 ■ Cosine 衰减阶段
调度训练不是一路全速前进。前 ~2% 步数做 Warmup：学习率从 0 线性升到峰值（比如 3e-4），让模型先用小步试探、避免一开始就大幅破坏随机初始化的权重。之后用 Cosine 衰减：按余弦曲线缓慢降到峰值的 ~10%。前期大步快走学大方向，后期小步精调做微调。整个曲线形状对最终模型质量影响很大——太激进会发散，太平缓会学不动。

④ GQA：Llama/DeepSeek 都在用的注意力省显存术

MQA vs GQA vs MHA · Key/Value 头数怎么省
GQAMHA（标准多头）：32 个 Q 头 × 32 个 K/V 头，最灵活但 KV Cache 最大。MQA（多查询）：32 个 Q 头 × 1 个 K/V 头，KV Cache 直接缩小 32 倍，但质量下降明显。GQA（分组查询）：折中方案——32 个 Q 头分成比如 8 组，每组共享 1 个 K/V 头。KV Cache 缩小 4 倍，质量几乎不掉。Llama-3（8组）、DeepSeek-V3 都用 GQA，这是长上下文能做起来的关键工程优化之一。
